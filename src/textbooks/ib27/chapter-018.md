## Chapter 14 — Workbook Architecture

### Learning objectives

- Explain each of the ten workbook sheets.
- Trace dependencies.
- Distinguish linked schedules from parallel analyses.

### Why it matters

A reviewer must know where to inspect an answer.

### Explanation

| Tab | Purpose |
|---|---|
| Sources | Registered inputs |
| ACLS Hist | Historical ACLS |
| VECO Hist | Historical VECO |
| TIEOUT | Reconciliation |
| ACLS Model | Standalone ACLS |
| VECO Model | Standalone VECO |
| Contribution | Economic contribution |
| Comps | Peer valuation |
| Merger | Mechanics and accretion |
| Spread | Dated market-data marks |

The workbook is generated by `research/03_scripts/build_workbook.py` and validated by `research/03_scripts/validate_workbook.py`.

### Project connection

The validator checks provenance metadata and source IDs. Specific metadata labels should be accepted only where the cited workbook cell or validator evidence establishes them; do not generalize an unverified label set.

### Worked example — Illustration

A forecast model cell can depend on a sourced historical value and an analyst growth assumption. The formula can be mathematically correct while still being assumption-driven. Use a verified workbook cell when teaching the frozen model; otherwise label the example as an illustration.

### Common mistakes

- Assuming every tab feeds every other.
- Ignoring comments and source IDs.
- Treating cached values as proof of recalculation.
- Treating validator metadata categories as universal without a cited cell.

### Checklist

- [ ] Know tab purpose.
- [ ] Inspect direct and ultimate inputs.
- [ ] Read cell metadata where cited.
- [ ] Identify human-review requirements.

### Takeaways

Workbook architecture makes analytical provenance inspectable.
