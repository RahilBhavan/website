5.3 TLSH: a fuzzy hash with a distance

TLSH (Trend Micro's locality-sensitive hash) slides a 5-byte window over the input, counts byte triplets into 128 buckets, and records each bucket as one of four levels relative to the quartiles of all the counts. Add a short header (a checksum, the length and quartile ratios) and you get a hash of about 70 hex characters. Two hashes give a distance: 0 means near-identical, and it grows as the byte statistics drift apart. There's no fixed maximum: the distance can run well past 300.

  • Input must be at least 50 bytes, and some low-variety inputs return no hash (TNULL). That's why tlsh_hash can return None.
  • Published cutoffs come from executables, not web pages. The config's tlsh_max_distance = 70 is a placeholder. The SPEC says to sweep 30 to 150 on your own labeled pages in week 3.
  • TLSH sees bytes, not structure. Two pages from one WordPress theme can be close even with different owners. That's one reason a single content signal never alerts on its own.

5.4 Shingles and Jaccard similarity

The structural signal ignores text and attributes. It walks the HTML and lists tag names in document order: html head meta title … body div nav a …. Then it takes every run of k = 5 consecutive tags, called a shingle. A page becomes a set of shingles, and two sets are compared by Jaccard similarity: shared shingles ÷ all distinct shingles, |A ∩ B| ÷ |A ∪ B|. 1 means the same set; 0 means nothing in common. Try it: change a tag in page B and watch which shingles stop matching.

5.5 MinHash: estimating Jaccard without the sets

Comparing a new page against every kit member means comparing many sets. MinHash compresses each set into a short signature. Pick a random hash function, hash every shingle, and keep only the smallest value. For two sets, the minimum is the same exactly when the shingle with the smallest hash in A ∪ B is in both sets. That happens with probability |A ∩ B| ÷ |A ∪ B|, which is the Jaccard. Repeat with 128 hash functions (minhash_perm) and count agreements. The fraction that agree is your estimate.

How noisy is 128?

Each agreement is a coin flip with probability J, so the estimate's standard error is √(J(1 − J) / 128). At J = 0.80 that's about 0.035. A pair whose true Jaccard is 0.78 will show ≥ 0.80 roughly 3 times in 10 (normal approximation). A hard cut-off at 0.80 is noisy for pairs close to it. That's fine when another family has to agree too, and one more reason never to alert on one signal.

5.6 The copy fingerprint: what separated the KCDA pages

The KCDA pages recovered from the Wayback Machine are WordPress + Elementor (Hello theme) behind Cloudflare. Their tag structure, paths and scripts are shared with thousands of ordinary Elementor sites. Once an Elementor background sample was added, they correctly stopped forming a kit on assets. What their builders reused was the sales copy.

copy_shingles takes the visible text, drops words that come from the domain's own brand (the label split on hyphens and digits, words of four or more letters), forms word 5-grams, hashes them with mmh3, and keeps the smallest 4,000 (a bottom-k sample, which estimates overlap consistently). Two pages are compared by containment: shared ÷ the smaller set. Containment, not Jaccard, because a long page containing a short page's whole copy is still a match.

5.7 Exact hashes: favicons, assets and inline scripts

Favicon mmh3. SSRD uses the Shodan recipe so its numbers match other tools: base64-encode the raw icon bytes with a newline every 76 characters (Python's base64.encodebytes), then take MurmurHash3 32-bit, signed. A different encoding of the same icon gives a different number, which makes pivots in Shodan or elsewhere silently fail. Default and CDN icons get zero weight through the denylist.

Try it in uv run python

import base64, mmh3; mmh3.hash(base64.encodebytes(b"\x00\x00\x01\x00toy-icon-bytes")) → -1857383559. Then try base64.b64encode (no newlines) on the same bytes and see the number change.

Assets. SHA-256 of same-origin JS and CSS files, skipping common libraries matched by library_asset_pattern (jQuery, Bootstrap, GSAP, analytics and so on). Free urlscan accounts return 404 on response bodies, so seed favicons can't come from urlscan. Asset SHA-256s from its result JSON still work.

Inline scripts over 200 characters are hashed with whitespace-only normalization. On Oct 17 they had been hashed after full normalization. That turned every chat-widget snippet's account number into 0, so all sites using the same widget got one hash, and kit-01 chained unrelated sites together. Account IDs are exactly what should survive, so now only whitespace is collapsed.

5.8 Page features, and values too common to mean anything

Family C reads the page: a normalized title (≥ 8 characters), Telegram and WhatsApp IDs, crypto-address patterns, response header order and the CMS generator. Contact IDs and addresses are private linking evidence. Hard rule 5: never interact with them.

A value seen on many unrelated sites (the default WordPress favicon, a popular theme's path, "Home") would link everything to everything. score.common_values counts how many distinct background and live hosts carry each value. Above max(3, 2% of hosts) it gets zero weight. Seed pages are deliberately left out of that count. Otherwise a large, genuine kit would denylist its own shared assets.

Why does the copy signal use containment instead of Jaccard?
A long landing page that contains a short page's entire copy, plus more, should still match. Jaccard would be dragged down by the extra text, while containment divides by the smaller set.
Why are seed pages excluded when building the common-value denylist?
A genuine kit with many seed members would push its own shared favicon or script over the "common" cut-off and erase the evidence that defines it.

6.1 Why "different families"

TLSH and tag-Jaccard both measure the HTML template. If two unrelated shops use the same WordPress theme, both fire together. Counting them as two independent confirmations would be double-counting one fact. So signals are grouped by what they measure: A content, B assets, C page features, D infrastructure. The SPEC rule is: alert only on ≥ 2 strong signals from different families among A/B/C; D only adds weight. Infrastructure is weak because the VCU release says the network used "Eastern European and American" hosts. Sharing Cloudflare or a big host's ASN means almost nothing.
