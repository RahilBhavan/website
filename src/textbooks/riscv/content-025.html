06 / DEPENDENCIESBUILD NOTES

A younger instruction can need an unfinished result

A data dependency exists when one instruction uses a result produced by another. A pipeline creates a timing problem if the consumer needs that value before normal writeback supplies it.

addi x1, x0, 7
add  x2, x1, x1

The ADD needs x1 in EX while the ADDI result has not yet reached WB. Reading the old register file value would give the wrong answer.

Forwarding, also called bypassing, routes an available result directly to the consumer. A stall waits when a required value does not exist yet. A flush discards work that should no longer execute, such as a wrong-path instruction.

The classic categories are data hazards, control hazards and structural hazards. This design avoids a shared instruction/data memory-port conflict by using separate ports. A single shared port would require arbitration or stalls.

Dependency is about meaning. Hazard handling is about when the machine can deliver the required value.

Forwarding selects the newest available value

Each EX input can come from its saved ID operand, a WB result, or a newer non-load result in MEM. The hardware compares destination and source register numbers.

value = saved_operand
if WB is a valid matching writer: value = WB.result
if MEM is a valid matching non-load writer:
    value = MEM.result

The last matching assignment wins in this combinational calculation. MEM represents a younger producer than WB, so its value has priority. x0 never participates as a producer.

Worked example

If an older instruction writes x1=5 and a newer instruction writes x1=8, a following consumer must use 8. Keeping the WB value when a newer MEM result matches would be wrong.

The same source selection feeds store data, branch comparisons, JALR bases and DOT4. Checking only ordinary ADD operands leaves important hazards unresolved.

06 / DEPENDENCIESBUILD NOTES

Writeback and decode can meet on one edge

The register file writes at a rising edge. ID/EX also captures its inputs at that edge. With nonblocking assignments, a register-file read expression can still see the old value during evaluation.

addi x1, x0, 7
addi x8, x0, 1
addi x9, x0, 2
add  x2, x1, x1

When the ADD reaches ID, the first ADDI is in WB. The core explicitly bypasses the WB value into the captured ID operand if the source register matches.

This WB-to-ID bypass solves a different timing boundary from the EX operand forwarding muxes. Both can matter in the same implementation.

A good test varies dependency distance. Adjacent instructions exercise one path. Two intervening instructions can exercise another. Also vary whether the dependency appears on rs1, rs2 or both.

For a store, distinguish the address base from the stored value. They are separate dependencies even though both use the same register file.

07 / THE LOAD-USE STALLBUILD NOTES

A load address is not the loaded value

lw  x1, 0(x0)
add x2, x1, x1

The load calculates its address in EX. Its data becomes available during MEM and is captured into MEM/WB. When the following ADD would enter EX, that loaded value is not yet available through this core's forwarding paths.

The interlock holds PC and IF/ID for one cycle, inserts an invalid EX entry and lets the older load advance. On the next cycle, the ADD enters EX and receives the loaded value from WB.

The hazard detector checks whether the ID instruction really uses rs1 or rs2. Bits in an immediate can occupy the rs2 field position without naming a source register. Treating those bits as a dependency causes unnecessary stalls.

This is a one-cycle stall only under the chosen memory and forwarding contract. A slower memory needs a different protocol and possibly more waiting.
