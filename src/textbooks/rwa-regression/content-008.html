The fix: wild cluster bootstrap

The wild cluster bootstrap was proposed by Cameron, Gelbach, and Miller (2008) and remains the consensus solution for few-cluster inference. The recommended variant for hypothesis testing is the restricted wild cluster bootstrap (WCR), which imposes the null hypothesis before resampling. The recipe:

  1. Fit the regression under the null hypothesis $H_0: \beta = \beta_0$ (typically $\beta_0 = 0$) by re-estimating with the constraint imposed, obtaining restricted coefficients $\tilde\beta$ and restricted residuals $\tilde e_{i,t}$.
  2. For each bootstrap iteration $b$ (typically B = 999 or 9,999): independently for each cluster, draw a single random sign $\omega_i \in \{-1, +1\}$ (Rademacher weights) — or from the 6-point Webb distribution for even better small-N performance.
  3. Construct bootstrap residuals $\tilde e^*_{i,t} = \omega_i \cdot \tilde e_{i,t}$ and bootstrap outcomes $Y^*_{i,t} = X_{i,t}\tilde\beta + \tilde e^*_{i,t}$.
  4. Re-fit the unrestricted regression to $Y^*$ and store $\hat\beta^*_b$.
  5. The bootstrap distribution of $\{\hat\beta^*_b\}_{b=1}^B$ approximates the sampling distribution of $\hat\beta$ under the null. The bootstrap p-value is the fraction of $|\hat\beta^*_b - \beta_0|$ at least as large as $|\hat\beta - \beta_0|$. Confidence intervals come from inverting the bootstrap test over a grid of $\beta_0$ values.

The key statistical fact: under $H_0$, the bootstrap distribution is asymptotically correct even as N gets small, because the sign-flips preserve the within-cluster correlation structure exactly. Roodman et al. (2019) showed in extensive simulations that WCR with Webb weights gives near-nominal coverage at N as small as 5. The unrestricted variant (WCU), which resamples around the unrestricted $\hat\beta$, is faster to compute but has noticeably worse coverage in our N=7 regime; we use WCR.

A separate small-N correction is also baked into fixest's analytical cluster-robust variance: the CR1 scaling $\frac{G}{G-1} \cdot \frac{N-1}{N-K}$ where $G$ is the number of clusters, $N$ is total observations, and $K$ is the number of parameters. Without this scaling the CR estimator is biased downward; with it, the bias is smaller but still material at $G = 7$. The bootstrap is what carries the day; the analytical SE is reported only alongside as a comparison.

Practical implementation in R

The wildboottest package implements the wild cluster bootstrap directly on top of a fixest regression: 

library(fixest)
library(wildboottest)

twfe <- feols(
  ihs_velocity_w ~ amm_listed_10k + log_mcap + log_holders +
                   token_age_weeks + ffr + log_defi_tvl |
                   token_id + week_num,
  data = panel
)

boot_result <- boottest(
  twfe,
  param   = "amm_listed_10k",
  clustid = "token_id",
  B       = 9999,
  type    = "webb"
)
summary(boot_result)
# returns bootstrap p-value and 95% confidence interval

For the Callaway-Sant'Anna estimator, the cleanest path is to use the bstrap argument of att_gt(), which performs the bootstrap natively on the ATT(g, t) components: 

cs_main <- att_gt(
  yname = "ihs_velocity_w",
  gname = "first_amm_week",
  idname = "token_id",
  tname = "week_num",
  data = panel,
  control_group = "nevertreated",
  bstrap = TRUE,
  biters = 9999,
  cband = TRUE  # uniform (rather than pointwise) confidence bands
)

cband = TRUE requests uniform confidence bands across the entire event-study curve. Without this, the per-event-time CIs would each have nominal coverage but the simultaneous coverage across all event times would be lower — and that simultaneous coverage is what matters for visual inspection of the plot.

What we report in the paper

Every standard error reported in any table is the wild cluster bootstrap version (Webb weights, B=9999). Every confidence interval on an event-study plot uses uniform bands. The paper's methodology section explicitly cites Cameron-Miller (2015) and Roodman et al. (2019) to justify these choices, and the appendix contains a comparison table showing conventional CR-SEs alongside bootstrap SEs so a sophisticated reader can see the small-N adjustment quantitatively.

The fundamental honesty

No amount of clever bootstrap fixes the basic fact that N=7 produces wide confidence intervals. If the true ATT on IHS(velocity) is 0.5 and the bootstrap-implied standard error is 0.3, our 95% CI is roughly (−0.1, 1.1) — we cannot rule out either a zero effect or a doubling effect. That's not a failure of the inference procedure; that's an honest reflection of the data. Chapter 12 covers exactly how the same N=7 makes pre-trend tests almost useless. Chapter 15 explains how to acknowledge this honestly in the paper.

Chapter 12 · Part III — Causal Inference

Pre-trend tests and their limits

Why a pre-trend test that fails to reject does not validate parallel trends — and the Roth (2022) critique that should keep you humble.

The standard pre-trends ritual

Every paper using a DiD design includes some version of this ritual. The author shows an event-study plot. The pre-treatment ATT coefficients are statistically indistinguishable from zero. The author writes: "consistent with parallel trends". Reviewer accepts. Paper publishes.

The implicit logic chain is:

  1. If parallel trends held in the pre-period, $\beta_{-1}, \beta_{-2}, \ldots, \beta_{-8}$ should all be zero on average.
  2. The estimates of those coefficients are close to zero.
  3. Therefore, parallel trends probably held.
  4. Therefore, the post-treatment estimates are unbiased.

Each individual step is reasonable. The chain as a whole is misleading, in a way that Jonathan Roth's AER: Insights 2022 paper made precise. The problem is step 2 — "close to zero" — which is a statement about statistical significance, not about the true underlying violation. And in a small sample, the gap between those two is enormous.

Why pretesting fails: a thought experiment

Suppose the true counterfactual trend for OUSG is slightly steeper than BUIDL's — say, the counterfactual would have increased by 0.3 IHS units per quarter, while BUIDL increases by 0.1 per quarter. That difference of 0.2 per quarter is a real parallel-trends violation. Over 8 pre-treatment weeks, it accumulates to about 0.4 units of "missing" trend in the pre-period.

In a panel with 7 units and large within-token noise, the standard error on each pre-treatment coefficient is approximately ±0.5. The pre-treatment coefficients will average around 0.4 — but with standard errors of ±0.5, each individual coefficient will fail to reject the null of zero at the 5% level. The pre-trend test will report "no evidence of pre-trend" and the author will declare parallel trends valid.

But the violation is real. The post-treatment estimate will be biased upward by the same 0.4 units that the pre-period violation was hiding. The "passing" pre-trend test gave false reassurance.

The Roth (2022) bias amplification

Roth's contribution goes further: he shows that conditional on passing the pre-trend test, the post-treatment estimate is biased in a predictable way. The selection effect ("we only kept publishing the papers whose pre-trends test passed") makes the conditional bias larger than the unconditional bias would be.

What Rambachan and Roth recommend instead

Rambachan and Roth (2023) — building on Roth's 2022 critique — propose honest DiD inference: rather than test the binary null of "parallel trends", pre-specify a set of plausible parallel-trends violations and report a confidence interval that is valid uniformly over that set. The R package HonestDiD implements this.

For example, you might pre-specify "the post-treatment PT violation is at most as large as the largest single pre-treatment coefficient I observed" — a natural benchmark called "relative magnitudes" restriction. The reported CI is then wider than the conventional one (because it accounts for the possibility of any PT violation in that range) but it is honest.

We report HonestDiD bounds as a robustness check in Chapter 14, using the relative-magnitudes restriction with $\bar M = 1$ (i.e., allow the post-treatment violation to be as large as the largest pre-treatment one). If the headline result still holds under this restriction — i.e., the HonestDiD CI still excludes zero — that is much stronger evidence than a passing pre-trend test.

What we actually do in the paper

  1. Report the event-study plot with pre-period coefficients.
  2. Report the formal pre-trend Wald test (joint null that all pre-coefficients = 0) but explicitly note its low power in N=7.
  3. Report the HonestDiD bounds for the main aggregated ATT.
  4. Discuss the qualitative shape of the pre-period coefficients — even if individually insignificant, are they trending in a worrying direction?
  5. Acknowledge in the limitations section that pre-trend testing in small N is severely underpowered and cannot fully validate the design.

The honest framing is: "we cannot prove parallel trends, but we can probe it from several angles and show that the headline finding is robust to plausible violations within the bounds the pre-period suggests." This is what reviewers in the modern DiD literature expect; the days of "the pre-trend test passed, therefore our design is valid" are over.

The deeper point

Even before Roth, a generation of methodologists has been saying that pre-trend tests provide weak evidence at best. The Roth result formalizes the intuition. The takeaway you should carry into the paper-writing process:

Internalize this

A pre-trend test that passes (fails to reject) provides evidence that the pre-period violation is small enough to be undetectable at the available power level. That is not the same as evidence that the violation is small enough to be ignorable in the post-period.
