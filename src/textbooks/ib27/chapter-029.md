## Chapter 24 — Human Review Gates

### Learning objectives

- Identify non-automatable release gates.
- Explain why they remain open.
- Use accurate release language.

### Why it matters

A static file can pass code tests and still fail in Excel, on paper, online, or in a live interview.

### Explanation

Open or separately verified gates include:

- Excel full recalculation and circular references.
- Grayscale print inspection.
- Authentic user recordings.
- Oral mastery without notes.
- Live GitHub Pages verification, which **remains unverified in the 2026-08-07 package**.
- Fresh SEC/SAMR review for current claims.

### Project connection

The release scorecard is “ALMOST.” Automated gates pass, while external packaging and human checks remain open. Gate lettering should be used only with the definitions in `research/09_qa/resume_ready_scorecard.md`.

### Worked example

Accurate wording:

> The workbook passed the independent validator on 2026-08-06; Excel-engine recalculation remains a human gate.

Inaccurate wording:

> The workbook is fully validated in Excel.

### Common mistakes

- Converting a placeholder recording into evidence of mastery.
- Calling local serving proof of GitHub Pages deployment.
- Presenting frozen prices as current.
- Treating automated page counts as print approval.

### Checklist

- [ ] Complete human gates.
- [ ] Record evidence.
- [ ] Update completion status.
- [ ] Narrow claims when gates remain open.

### Takeaways

Human gates are not bureaucracy; they test different properties.
