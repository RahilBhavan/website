RAHIL BHAVAN / OPERATIONS NOTE · 10 NOV 2026

Stop asking a model to wait.

Six changes to reduce repeated context and idle model calls. Explore the evidence, the replacement and its limits.

01 / Waiting

62.0M input tokens for status-only turns

The bank runtime audit identified 145 measured turns whose only tool call checked available capacity.

Why it caused overhead
A cheap machine observation loaded a model conversation first. A quiet reply still consumed context.
What changed
A local Python watcher now checks readiness every minute. Blocked capacity and unchanged commands invoke no model.
What this does not prove
These are avoidable-check candidates, not a dollar bill. Cached input is included in total input. Actual savings remain unmeasured.
02 / Polling

Wait for a change, then wake the owner

The fraud session contained 138 thread-read calls. The count alone does not make every read wasteful.

Why it caused overhead
Repeated model reads can discover the same unchanged progress. A missing session handle can also trigger duplicate work.
What changed
Pending commands retain PID, start-time, boot and result-file identities. The watcher sends one readiness event per checkpoint generation.
What this does not prove
This is a mechanism diagram, not a measured before/after token reduction. A completion hint never proves a passing check.
03 / Context

Keep a compact record of what happens next

Continuation packets preserve the contract, canonical state, pending command references and the next action.

Why it caused overhead
Old research and tool output can follow every small continuation step. Clearing context blindly can lose work identity and authority.
What changed
Packets point to canonical sources instead of copying the transcript. Checkpoints re-arm after progress; unchanged continuation is refused.
What this does not prove
T3 did not persist fresh-session mode. Existing owners still use continuing sessions. Character counts are not token counts.
04 / Reviews

Narrow the investigation; keep required review

The requested AI-guide swarm and council were authorized. Agent count alone is not proof of waste.

Why it caused overhead
Overlapping reviewers can reload the same evidence or rerun unrelated checks after a small correction.
What changed
One owner uses a canonical evidence packet. Follow-up investigation targets changed artifacts and invalidated checks.
What this does not prove
Independent checks, exact-head acceptance, full reviews and original repair limits still apply. Scoping is instruction-level guidance.
05 / Instructions

46.8% less always-loaded instruction text

Detailed workflows moved into a task router. The original sections were checked for preservation.

Why it caused overhead
Unrelated calendar, content and networking procedures loaded on tasks that did not need them. Relevant rules became harder to find.
What changed
Essential authority and safety rules remain global. The router loads only the relevant workflow section and its current skill.
What this does not prove
This measures file size, not runtime token savings. The app-injected skill catalog remains unchanged.
06 / Accounting

Large usage is not the same as wasted usage

The selected runtime session used 247.8M lifetime input tokens. Only a specific subset met the conservative status-only classifier.

Why it caused overhead
Adding cache reads to Codex input double-counts them. Summing cumulative snapshots also inflates usage.
What changed
The read-only audit uses owner-attributed cumulative maxima. It separates classified overhead candidates from total usage.
What this does not prove
Other turns are not classified as useful or wasteful. These are local session totals, not daily spend, account quota or all-device usage.
Installation evidence: 10 tests passed. One live event reached the runtime owner, which completed and re-armed a command wait. Fraud stayed asleep while its watched commands were unchanged. This snapshot does not establish ongoing uptime or token savings.
