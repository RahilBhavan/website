12.4Conditioning & Stability

When the algorithm is the problem, not the precision

[A12.4.1]

Condition Number

linear algebra

For a problem y = f(x), the condition number measures how much a small change in x can move y. For matrix multiply y = Ax, it is κ(A) = σ_max(A) / σ_min(A). If κ ≈ 10⁶, you lose ~6 decimal digits when solving with A. FP32 has ~7 digits — you have 1 left. Reducing to FP16 (3 digits) on an ill-conditioned matrix produces nonsense.

Practical guideline:

  • κ < 10² → FP16/BF16 fine.
  • 10² ≤ κ < 10⁵ → mixed precision with FP32 accumulator.
  • κ ≥ 10⁵ → keep FP32 throughout, or rescale the problem.
[A12.4.2]

Catastrophic Cancellation

subtraction

Subtracting two nearly equal numbers leaves only their (small) difference, with the precision of the difference. Example: (1 + 1e-8) - 1 in FP32 returns 0 because 1e-8 is below the FP32 ULP at magnitude 1. Common offenders:

  • Mean-centering large tensors (x - mean(x)) before computing variance.
  • Softmax numerator/denominator with poorly chosen max-subtraction.
  • Naive variance formula E[X²] − E[X]² instead of Welford.

Fix by algebraic rearrangement or higher precision intermediates.

12.5Mixed Precision & Loss Scaling

Half the bits, twice the throughput, none of the divergence — if you do it right

[A12.5.1]

Automatic Mixed Precision (AMP) Recipe

training

Standard AMP for training:

  1. Store weights as FP32 master copies, cast to FP16/BF16 for forward and backward passes.
  2. Compute matmuls and convolutions in FP16/BF16 with FP32 accumulators (Tensor Cores).
  3. Keep softmax, layernorm, loss, and optimizer steps in FP32.
  4. Loss scaling (only for FP16, not BF16): multiply loss by S (typically 2¹⁰–2¹⁶) before backward so gradient magnitudes stay above FP16's subnormal threshold; unscale before applying to optimizer.

BF16 has the FP32 exponent range, so loss scaling is unnecessary — at the cost of fewer mantissa bits.

12.6Determinism on the GPU

Same input, same kernel, same hardware — different answer

[A12.6.1]

Sources of Non-Determinism

determinism

The same GEMM kernel can return bit-different results across runs because of three independent sources:

  1. Atomic operations — order of atomicAdd across blocks depends on scheduler. Solution: use deterministic reduction (segmented or tree).
  2. Algorithm selection — cuBLAS and cuDNN heuristically pick different kernels based on cache state. Disable with CUBLAS_PEDANTIC_MATH_MODE, CUBLASLT_ALGO_CONFIG pinning, or torch.use_deterministic_algorithms(True).
  3. Reduction order — split-K and stream-K change the order of K-axis additions; FP non-associativity makes the result bit-different.

If you need byte-identical reproducibility, accept the typical 10–30% performance cost and lock all three.

Quantization & Sparsity:
Shrinking the Operands Without Breaking the Math

Learning goal. Tensor Cores double their throughput every time you halve the operand width. INT8 is 2× FP16; INT4 is 4×; sparse-INT8 is 8×. But each step trades precision for speed. This chapter teaches you the four quantization schemes you'll meet (per-tensor, per-channel, per-token, group-wise), the FP8 formats and when each one is right, how 2:4 structured sparsity is enforced at the hardware level, and how to fuse dequant + GEMM + bias + activation into a single kernel.

13.1The Quantization Spectrum

From FP32 down to 1-bit, what each tier actually costs

[A13.1.1]

Five Quantization Granularities

quantization
  • Per-tensor — one (scale, zero_point) for the whole tensor. Cheapest, lowest accuracy.
  • Per-channel — one per output channel. Standard for weights.
  • Per-token / per-row — one per activation row. Standard for transformers.
  • Group-wise — split a tensor into groups of e.g. 64 consecutive values, one scale per group. AWQ, GPTQ use 128-group.
  • Sub-channel — multiple scales per channel, used by FP4 schemes (NVFP4 has two-level scale).

The finer the granularity, the more accuracy you preserve, but the more metadata bandwidth you spend.

[A13.1.2]

Symmetric vs Affine Quantization

scheme

Symmetric: q = round(x / scale). Zero in the float domain maps to 0 in the int domain. Cheaper kernels (no zero-point arithmetic), but wastes the bottom half of the int range when x is non-negative (e.g. after ReLU).

Affine: q = round(x / scale + zero_point). Uses the full int range, at the cost of one extra add per multiply (which can be folded into the bias).

Modern LLM inference is largely weight-only symmetric (W4A16, W8A16) with affine activations only where necessary.

13.2INT8 GEMM Kernels

The first Tensor-Core integer pipeline

[A13.2.1]

IMMA — Integer Matrix-Multiply-Accumulate

tensor cores

Available since Turing. Sample shape on Ampere: m16n8k32 s8s8s32 — A and B are INT8 tiles, accumulator is INT32. Throughput: 2× the FP16 Tensor-Core rate. PTX form:

mma.sync.aligned.m16n8k32.row.col.s32.s8.s8.s32 {d0,d1,d2,d3}, {a0,a1}, {b0}, {c0,c1,c2,c3};

The s8.s8.s32 means: A is signed INT8, B is signed INT8, accumulator is signed INT32. The INT32 accumulator never overflows for K ≤ 2³¹/256² ≈ 32K.

// Per-channel symmetric quant for weights, per-token affine for activations.
struct Quant {
    int8_t*  q_data;    // quantized values
    float*   scale;     // scale per channel or per row
    int32_t* zero;      // zero point (0 if symmetric)
};

void gemm_int8(const Quant& A, const Quant& B, float* C,
               int M, int N, int K, cudaStream_t s) {
    // 1) Call the IMMA kernel that produces an INT32 partial sum.
    int32_t* C_int;
    cudaMallocAsync(&C_int, M * N * sizeof(int32_t), s);
    imma_gemm_kernel<<<grid, block, 0, s>>>(A.q_data, B.q_data, C_int, M, N, K);
    // 2) Dequant + bias + activation in a fused epilogue:
    dequant_epilogue<<<..., s>>>(C_int, A.scale, B.scale, C, M, N);
    cudaFreeAsync(C_int, s);
}

[A13.3.1]
