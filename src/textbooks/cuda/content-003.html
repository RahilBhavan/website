0.3Linear Algebra You Cannot Skip

The objects, the operations, the BLAS hierarchy

Reading order. Vectors → matrices → matrix-vector → matrix-matrix → BLAS levels. Each step adds one dimension's worth of structure and roughly an order of magnitude of arithmetic intensity. The whole textbook is about why level-3 BLAS is where GPUs win.
[[A0.3.1]]

Vector — a 1-D array of numbers, with a contract

linalg

A vector of length n is an n-tuple of numbers, stored contiguously. The contract that makes it a "vector" rather than just an array is that only certain operations preserve meaning: addition componentwise, scalar multiplication, dot product, norm. A "vector" in CUDA code is usually a pointer plus a length plus a stride. The stride is not the same as the length: two vectors that share a stride but are offset can be views into different rows of the same matrix without copying.

Matrix layout — row-major vs column-major and leading dimension

linalg

An M×N matrix flattened to memory needs an ordering convention. Row-major (C, NumPy default): row 0 contiguous, then row 1, etc.; element (i,j) sits at offset i·N + j. Column-major (Fortran, BLAS, cuBLAS): column 0 contiguous; offset is i + j·M. Most working CUDA kernels actually carry a leading dimension (often called lda): the stride in memory between successive rows or columns, which can be larger than the logical dimension to satisfy alignment constraints. Bug class: confusing lda with the matrix dimension, getting addresses right for the first few elements, and producing silently wrong results far from the corner.

cuBLAS inherited Fortran column-major from netlib BLAS. To call it from row-major C code you typically swap the operands and the transpose flags: cublasSgemm(...A, B...) on row-major is equivalent to cublasSgemm(...Bᵀ, Aᵀ...) on column-major. This is the single most common cuBLAS bug for newcomers.

GEMV — matrix-vector multiply, the "memory-bound" canary

linalg

y = αAx + βy. For an M×K matrix and a length-K vector, the FLOP count is 2·M·K and the memory traffic is M·K + K + M reads/writes. Arithmetic intensity is therefore ≈ 2 FLOPs / element of A read — almost identical to a streaming copy. On any modern accelerator GEMV is dead memory-bound; it is the lower bound on a GEMM's intensity if you fail to reuse A. The decode step of an autoregressive LLM is just a stack of GEMVs and that's why those decode tokens are slow.

GEMM — the operation this entire book is about

linalg

C = αA·B + βC, with A being M×K, B being K×N, C being M×N. FLOP count: 2·M·N·K. Memory traffic if nothing is reused: M·K + K·N + 2·M·N. Arithmetic intensity if nothing is reused: ≈ 2·K elements of work per element of memory loaded, which for K=4096 is ~8 KFLOPs/byte (FP16) — well into compute-bound territory. That intensity is the entire reason GPUs and tensor cores exist for matmul.

The catch: nothing is reused only holds if you actually do the reuse. A naive triply-nested loop has the same intensity as GEMV because each thread reloads A and B from global memory K times. The job of every kernel in Ch 2, every tile transformation in Ch 3, and every cuBLAS trick in Ch 5 is to capture the intensity that the algebra promises.

GEMM offers ~K FLOPs per byte of A or B, but only if your kernel reuses each loaded element ~K times before evicting it. Reuse is the whole game.

BLAS levels 1 / 2 / 3 — a hierarchy of arithmetic intensity

interface
  • Level 1 Vector-vector ops: axpy, dot, norm. O(n) work, O(n) memory. Intensity ~1. Always memory-bound.
  • Level 2 Matrix-vector ops: gemv, trsv, ger. O(n²) work, O(n²) memory. Intensity ~2. Memory-bound on any modern accelerator.
  • Level 3 Matrix-matrix ops: gemm, syrk, trsm. O(n³) work, O(n²) memory. Intensity scales with the tile dimension. The only level where the GPU can saturate its FLOP rate.

BLAS originated as a Fortran linear-algebra library standard in the 1970s–80s. cuBLAS, MKL, OpenBLAS all implement the same interface. The library taxonomy maps to the roofline (§1.6) exactly: Levels 1 and 2 live on the memory-bound slope; Level 3 lives on the compute-bound ceiling — if you tile it right.
