19.2TMA in Detail

The async-bulk-copy instruction that replaces a warp of cp.asyncs

[A19.2.1]

The Tensor Map Descriptor

tma

A TMA descriptor is a 128-byte opaque struct (CUtensorMap) created on the host with cuTensorMapEncodeTiled and passed to the kernel as a kernel param (which the driver staged into constant memory). It encodes:

  • Global base, per-dimension extents and strides.
  • Box size per dimension (the tile shape).
  • Element type (FP16/BF16/FP8/INT8/…).
  • Interleave mode (NONE, 32B, 64B, 128B — for image data).
  • Swizzle pattern (NONE / 32B / 64B / 128B).
  • L2 promotion policy and OOB fill behavior (zero, constant, copy).

A single PTX cp.async.bulk.tensor.{1d,2d,3d,4d,5d}.shared::cluster.global instruction, issued by one thread, kicks off the entire tile copy and signals an mbarrier on completion.

19.3wgmma — Warp-Group MMA

Hopper's new instruction that operates on 4 warps at once

[A19.3.1]

128 Threads, One MMA

wgmma · hopper

Ampere's mma.sync issues 1 instruction per warp (32 threads). Hopper introduces wgmma.mma_async which issues 1 instruction per warp group (4 warps = 128 threads), with the operands implicitly distributed across the warps. Sample shape: m64n128k16 fp16fp16fp32.

Asynchronous semantics: the wgmma fires off, the warps continue, and later commit/wait instructions stall until results are ready. This enables tighter overlap with the TMA loads above.

// Producer warp issues TMA copy and arrives on mbarrier.
cp.async.bulk.tensor.2d.shared::cluster.global  [smem],   [desc, coords], [mbar];
mbarrier.arrive.expect_tx.b64                  [mbar],    bytes;

// Consumer warp group waits, then issues wgmma.
mbarrier.try_wait.parity.b64  P0, [mbar], phase;
@P0 bra wait;

wgmma.fence.sync.aligned;
wgmma.mma_async.sync.aligned.m64n128k16.f32.f16.f16.f32  {d…}, descA, descB, scaleD, scaleC;
wgmma.commit_group.sync.aligned;
wgmma.wait_group.sync.aligned  0;

19.4Thread-Block Clusters & DSMEM

A new level above the threadblock

[A19.4.1]

Clusters: 16 Blocks That Talk Directly

cluster

A Hopper cluster is a group of up to 16 thread blocks (8 portably) that are guaranteed to be co-scheduled on adjacent SMs and can directly read/write each other's shared memory via DSMEM (Distributed Shared Memory). New launch syntax:

__cluster_dims__(2, 2)
__global__ void clustered_gemm(...) {
    namespace cg = cooperative_groups;
    cg::cluster_group cluster = cg::this_cluster();
    cluster.sync();      // cluster-wide barrier
    int* peer = cluster.map_shared_rank(my_smem_ptr, peer_rank);
    *peer = value;       // write into another block's SMEM
}

Why it matters: a 256×256 output tile that was too big for one block's SMEM can now span 4 blocks × 64×64 SMEM each, with one-hop DSMEM access. Used heavily in FlashAttention-3 and Hopper CUTLASS GEMMs.

19.5The Transformer Engine

Dynamic FP8 scale management at run time

[A19.5.1]

What the TE Library Actually Does

transformer engine

NVIDIA's Transformer Engine library wraps Hopper's FP8 Tensor Cores. Each forward pass:

  1. Reads a histogram of recent activation magnitudes for each tensor.
  2. Picks an FP8 scale per tensor that maximizes representable range without saturating.
  3. Quantizes the tensor to FP8 with that scale.
  4. Issues the FP8 Tensor-Core GEMM.
  5. Records new statistics for the next iteration.

Without TE-style adaptive scaling, FP8 training diverges. With it, models train to within 0.1 perplexity of FP16/BF16 at >2× the throughput.

19.6Blackwell Preview

What's already known about sm_100 / B200

[A19.6.1]

FP4, Generation-5 Tensor Cores, 5th-Gen NVLink

blackwell
  • FP4 (NVFP4) — 4-bit float with two-level scaling. ~2× FP8 throughput on Tensor Cores. New PTX mma.sync shapes.
  • Tensor Memory — a new dedicated on-chip storage feeding Tensor Cores, separate from the register file. Reduces register pressure dramatically.
  • 2nd-Gen Transformer Engine — adds dynamic FP4 scaling, supports MX (microscaling) formats.
  • 5th-gen NVLink — 1.8 TB/s per GPU, 18-link NVSwitch fabric scaling to 576-GPU domains.
  • 2-die "chiplet" GPU — first NVIDIA GPU built as two reticle-limit dies stitched with a 10 TB/s NV-HBI link, presented to software as a single device.

What stays the same: the SIMT execution model, the shared-memory bank layout, the CUDA C++ surface. Everything you learned in chapters 1–17 still applies — Blackwell mostly adds more dimensions to the same Tensor-Core / TMA / cluster axes Hopper opened.

20.1C++ for CUDA Kernel Writers

The subset you actually need

[A20.1.1]

Templates, constexpr, and Why CUTLASS Looks Like That

c++

The C++ features every CUDA kernel author should know:

  • Function templates — let one kernel cover multiple tile sizes. template <int BM, int BN, int BK> __global__ void gemm(...).
  • constexpr — compile-time computation; the compiler folds BM * BK into an immediate.
  • auto + decltype — concise return types; useful for cooperative-groups / cute lambdas.
  • std::integer_sequence / index_sequence — unrolled loops at compile time without macros.
  • if constexpr — pick code paths based on template params with no branch in the binary.
  • CRTP (Curiously Recurring Template Pattern) — static polymorphism for epilogues without virtual cost.
  • SFINAE / concepts — overload resolution that respects device constraints.

Keep away from: exceptions (forbidden on device), RTTI, virtual functions across host/device, anything that allocates with global new in a kernel.

template <int BM, int BN, int BK, int TM, int TN>
__global__ void gemm(const float* A, const float* B, float* C, int M, int N, int K) {
    float acc[TM][TN] = {};

    #pragma unroll
    for (int k = 0; k < BK; ++k) {
        #pragma unroll
        for (int i = 0; i < TM; ++i) {
            #pragma unroll
            for (int j = 0; j < TN; ++j) {
                acc[i][j] = __fmaf_rn(/* loads */, /* loads */, acc[i][j]);
            }
        }
    }
    // ...store acc to C
}

20.2Driver, Toolkit, Install

How to set up a benchmark-ready box

# 1. Match driver to toolkit. CUDA 12.4 needs >= 550.54.
sudo apt-get install -y nvidia-driver-555
sudo reboot

# 2. Install the toolkit, not the bundled driver.
wget https://developer.download.nvidia.com/compute/cuda/12.4.1/local_installers/cuda_12.4.1_550.54.15_linux.run
sudo sh cuda_12.4.1_550.54.15_linux.run --toolkit --silent

# 3. Path setup.
echo 'export PATH=/usr/local/cuda-12.4/bin:$PATH' >> ~/.bashrc
echo 'export LD_LIBRARY_PATH=/usr/local/cuda-12.4/lib64:$LD_LIBRARY_PATH' >> ~/.bashrc
source ~/.bashrc

# 4. Verify.
nvidia-smi
nvcc -V
nsight-compute --version

# 5. (Benchmark prep) Lock the clocks.
sudo nvidia-smi -pm 1
sudo nvidia-smi --lock-gpu-clocks=1410,1410   # set to the boost clock you want
sudo nvidia-smi --lock-memory-clocks=1593,1593

# 6. (Optional) Enable persistence and disable autoboost.
sudo nvidia-smi --auto-boost-default=0
