The Two FP8 Formats

FP8 · hopper

Hopper introduces two FP8 formats following the OCP FP8 spec:

  • E4M3 — 1 sign, 4 exponent, 3 mantissa. Range ±448, ~3 ULP precision. Used for activations and weights in forward pass.
  • E5M2 — 1 sign, 5 exponent, 2 mantissa. Range ±57344, ~7 ULP precision. Used for backward gradients (wider range, less precision).

Hopper Tensor Cores accept any mix: fp8_e4m3 × fp8_e4m3 → fp32, fp8_e5m2 × fp8_e4m3 → fp16, etc. The Transformer Engine library auto-selects format per tensor based on histogram statistics.

Used by§19.5 Transformer Engine
Accuracy hint

FP8 inference of an LLM can match FP16 within 0.1 perplexity if (a) weights and activations use per-tensor scales updated every forward, (b) attention logits stay in FP16, and (c) layer-norm runs in FP32. Skipping any of these makes the model diverge within a few hundred tokens.

13.4Sub-Byte Weights — INT4 & FP4

When the GEMM is memory-bound, every bit you save is throughput

[A13.4.1]

Packing & Decoding INT4

int4

Two INT4 values share one byte. The kernel decodes them on load with shifts and masks, multiplies the FP16 activations, accumulates in INT32 (or FP32 after dequant). The 2× memory savings over INT8 plus the unchanged Tensor-Core throughput means INT4 weight-only quantization is the workhorse of consumer LLM inference. Marlin, AWQ, and ExLlamaV2 are all INT4 weight kernels with different tile/layout choices.

[A13.4.2]

NVFP4 — Blackwell's 4-bit Float

blackwell

Blackwell adds an FP4 format (E2M1) and Tensor-Core instructions that consume it directly. Two-level scaling: each block of 16 FP4 values has an FP8 scale, and each block of 16 of those has an FP32 scale. The hardware decodes and rescales on the fly. Total memory cost: ~4.5 bits/value. Theoretical 2× over FP8 throughput on Blackwell Tensor Cores.

13.52:4 Structured Sparsity

Free 2× from the hardware if your weights cooperate

[A13.5.1]

The 2:4 Pattern

sparsity

In every group of 4 consecutive weights, exactly 2 must be zero. The hardware stores only the 2 non-zeros plus a 2-bit index (0b00–0b11) telling it which positions are non-zero. A sparse Tensor Core multiplies a sparse 16×K weight tile by a dense K×N activation tile in the same cycle count as a dense 16×(K/2) tile — i.e., 2× throughput.

Restrictions:

  • 2:4 along the K-axis of the weight tile (not the M-axis).
  • K must be a multiple of 4 (16 for FP16/BF16, 32 for INT8).
  • Activations stay dense; only the weight side is sparse.

Practical approach: train dense, prune to 2:4 with the ASP (Automatic Sparsity) workflow, fine-tune for ~10% of original training cost, deploy. Accuracy loss on most LLMs is < 0.5%.

13.6Dequant Fusion & Epilogues

Why a separate dequant kernel is always wrong

[A13.6.1]

The Epilogue Belongs in the GEMM

fusion

An INT8 GEMM produces an INT32 partial sum that you need to dequantize, add a bias to, then apply an activation (GeLU, SiLU). If you write three separate kernels, you re-read and re-write the M×N tile to/from global memory twice. Fusing the dequant + bias + activation inside the GEMM epilogue — the code that runs after the K loop — keeps the tile in registers until the final store. Savings: typically 30–50% end-to-end latency on small-M LLM decode.

CUTLASS exposes this via the EpilogueOp template parameter. Triton fuses it automatically when you write tl.store(c_ptr, activation(c_int32 * scale + bias)). Raw CUDA: you write the epilogue yourself, after the final mma.sync and before the global stmatrix.

Flash Attention &
IO-Aware Algorithms

Learning goal. FlashAttention is the canonical example of an algorithm that beat the textbook math by being honest about the memory hierarchy. Understanding it teaches you a generalizable design pattern — tile so the inner loop stays in shared memory, recompute instead of storing, and online-update the dependent statistics — that you can apply to softmax, layer norm, scan-based loss functions, and any kernel that touches a large intermediate.

14.1Why Attention Is Memory-Bound

The N² intermediate that doesn't fit anywhere

[A14.1.1]

Standard Attention's IO Cost

attention

Standard scaled-dot-product attention on a sequence of length N with head dimension d:

S = Q · Kᵀ // (N × d) · (d × N) → N × N P = softmax(S / √d) // N × N O = P · V // (N × N) · (N × d) → N × d

Compute cost: O(N²·d) FLOPs. Memory cost: the N×N matrix S (or P) must be written to global memory and read back — 2·N² FP16 reads/writes. For N = 8192, that's 256 MB per attention head, on a chip whose L2 is 50 MB. The kernel becomes memory-bound long before it becomes compute-bound.

Arithmetic intensity:

AI ≈ N²·d / (N² + N·d) ≈ d FLOPs/byte

For d = 64, AI ≈ 64. The A100 ridge point is around 290. So we are 4.5× below the roofline ridge — memory-bound by construction.

14.2Online Softmax — The Mathematical Trick

Update the normalizer as new blocks arrive, without storing the unnormalized scores

[A14.2.1]

Streaming Maximum & Streaming Sum-Exp

softmax

Naive softmax requires three passes: find max, subtract max and exp, divide by sum. The flash idea: process the input in blocks of size B, and after each block update the running (max, sum, output) tuple such that the final answer is exact. For two blocks with statistics (mᵢ, ℓᵢ) and (mⱼ, ℓⱼ):

m_new = max(mᵢ, mⱼ) ℓ_new = exp(mᵢ - m_new)·ℓᵢ + exp(mⱼ - m_new)·ℓⱼ O_new = (exp(mᵢ - m_new)·ℓᵢ / ℓ_new)·Oᵢ + (exp(mⱼ - m_new)·ℓⱼ / ℓ_new)·Oⱼ

The update touches only the running scalars and the current output tile — never the full N×N S. This is the algorithmic core of FlashAttention.

Used by§14.3 FA-1

14.3FlashAttention-1 Walkthrough

The reference algorithm, block-by-block

// Inputs: Q (N x d), K (N x d), V (N x d)
// Outputs: O (N x d)
// Block sizes: Br rows of Q, Bc rows of K/V

for (i = 0; i < N; i += Br) {
    // Load a Br × d block of Q into shared memory.
    Q_i = load_tile(Q, i, Br);
    // Running statistics for this Q-block.
    m_i = -inf;                     // running max
    l_i = 0;                        // running sum-exp
    O_i = zeros(Br, d);             // running output

    for (j = 0; j < N; j += Bc) {
        // Load a Bc × d block of K and V.
        K_j = load_tile(K, j, Bc);
        V_j = load_tile(V, j, Bc);

        // Compute S_ij = Q_i · K_jᵀ (Br × Bc) — stays in shared mem.
        S_ij = mma(Q_i, transpose(K_j));   // Tensor Core GEMM

        // Apply causal mask if needed.
        if (j > i) S_ij = mask(S_ij);

        // Online softmax update.
        m_ij     = rowmax(S_ij);
        m_i_new  = max(m_i, m_ij);
        P_ij     = exp(S_ij - m_i_new);
        l_ij     = rowsum(P_ij);
        l_i_new  = exp(m_i - m_i_new) * l_i + l_ij;

        // Update output: rescale prior, add new contribution.
        O_i = (exp(m_i - m_i_new) * l_i / l_i_new) * O_i
            + (1.0 / l_i_new) * mma(P_ij, V_j);

        m_i = m_i_new;
        l_i = l_i_new;
    }
    store_tile(O, i, O_i);
}
Why this is faster

The N×N matrix S is never written to global memory — it lives in shared memory as a Br×Bc block, then disappears. HBM traffic drops from O(N²) to O(N·d) (the four input/output tensors). For N = 8K, d = 64, that's a 60× reduction in memory traffic, which on an A100 translates to a 4–7× speedup over a fused-but-non-IO-aware implementation.

14.4FlashAttention-2 & 3

What changed when Tri Dao revisited the design

[A14.4.1]

FA-2 — Work Partitioning

fa2

FA-1 split the grid along (head, batch). FA-2 adds a third axis: sequence. Multiple thread blocks now collaborate on different Q-blocks of the same head, increasing parallelism for the short-context, large-batch case. Other tweaks:

  • Reduce the rescaling chain by deferring the 1/ℓ division to the end.
  • Refactor inner loops so the producer-consumer pipeline interleaves load and MMA more tightly.
  • Avoid the implicit transpose of K by storing K already transposed.

Net result: ~2× throughput vs FA-1 on A100, ~70% of theoretical Tensor-Core peak.

[A14.4.2]

FA-3 — Hopper-Native

fa3 · hopper

FlashAttention-3 targets Hopper's TMA, wgmma, and warp specialization. It splits the warps inside a block into a producer warp group that issues TMA loads and a consumer warp group that runs wgmma on the loaded tiles. The two communicate via an mbarrier, so loads and math overlap at fine granularity. Reaches ~75% of H100 Tensor-Core peak FP16.
