Stream-Ordered Memory (cudaMallocAsync)

allocator · pools

Since CUDA 11.2 each device has a default memory pool. cudaMallocAsync(ptr, n, stream) queues an allocation that completes when stream reaches it; the pool reuses freed blocks instead of returning them to the driver. Benefits:

  • Allocation cost drops from microseconds to a handful of instructions for typical sizes.
  • Correctness across streams is automatic via cudaMemPoolAttrReleaseThreshold and stream events.
  • Works inside CUDA Graphs (legacy cudaMalloc does not).

Always prefer cudaMallocAsync for short-lived per-iteration buffers in training/inference loops.

// Tunable pool: keep up to 4 GB of freed blocks, never trim below 256 MB.
cudaMemPool_t pool; cudaDeviceGetDefaultMemPool(&pool, 0);
uint64_t threshold = 4ull * 1024 * 1024 * 1024;
cudaMemPoolSetAttribute(pool, cudaMemPoolAttrReleaseThreshold, &threshold);

cudaStream_t s; cudaStreamCreate(&s);
for (int iter = 0; iter < 1000; ++iter) {
    float* tmp;
    cudaMallocAsync(&tmp, N * sizeof(float), s);   // O(1) — reuses pool memory
    my_kernel<<<grid, block, 0, s>>>(tmp, /*...*/);
    cudaFreeAsync(tmp, s);                          // queued, no host stall
}
cudaStreamSynchronize(s);

11.6TMA & Async Bulk Copy (Hopper)

Move an entire tile with a single descriptor

[A11.6.1]

What the Tensor Memory Accelerator Actually Does

hopper · tma

On Ampere, copying an N-element tile from global to shared takes N/4 cp.async instructions, each issued by a thread. On Hopper, the TMA does it in one instruction (cp.async.bulk.tensor) issued by a single elected thread, given a precomputed descriptor that encodes:

  • Global base pointer and per-dimension strides.
  • Tile shape (up to 5-D).
  • Shared-memory destination, with optional swizzle pattern (SWIZZLE_NONE, SWIZZLE_32B, SWIZZLE_64B, SWIZZLE_128B).
  • Out-of-bounds policy (zero-fill or padding).

The TMA computes addresses, issues coalesced loads, and signals completion via an mbarrier. The warps doing math never compute an address. Result: more compute units do useful work, and the address-generation pressure that limited Ampere disappears.

11.7Texture, Constant, and Read-Only Cache

Three under-used memory paths that still matter

[A11.7.1]

Constant Memory — Broadcast or Bust

constant memory

64 KB of read-only memory cached by a small dedicated cache per SM. The win condition: all threads in a warp read the same address. The hardware broadcasts the value to all 32 lanes in a single cycle. Different addresses serialize. Use for: scalar hyperparameters, RoPE base/scale, lookup tables shared by every thread.

Kernel parameters (the arguments of __global__) live in constant bank 0 implicitly — that's the cmem[0] in ptxas output.

[A11.7.2]

Texture & Surface — Still Useful in 2026

texture · surface

Texture memory is global memory accessed through a special read path that adds (a) hardware bilinear interpolation, (b) clamp/wrap addressing, (c) 8-/16-/32-bit normalized loads, and (d) a separate cache that does not pollute L1. Modern uses:

  • Image and volume processing where bilinear interpolation is free.
  • Look-up tables larger than constant memory where reads are spatially correlated.
  • Sparse/scattered reads where you want a cache distinct from L1.

The __ldg(ptr) intrinsic gives you the read-only cache without the texture object machinery — usually enough for modern kernels.

Numerical Methods:
What FP32 Promises and What It Actually Delivers

Learning goal. Floating-point math on a GPU is not the same as floating-point math you grew up with. Order of operations changes results, parallel reductions are non-deterministic by default, tensor cores accumulate to a different precision than they multiply with, and a "fast-math" flag can silently change your model's accuracy. This chapter teaches you to predict the numerical behavior of a kernel, prove it, and choose the right precision strategy.

12.1IEEE 754 Beyond the Bit Layout

Rounding modes, subnormals, ULPs, and what NVIDIA chose

[A12.1.1]

Rounding Modes

IEEE 754

IEEE 754 defines four rounding modes. NVIDIA hardware supports all four per instruction, but the compiler default is round-to-nearest-even (RTNE). The PTX suffixes are .rn (nearest-even), .rz (toward zero / truncation), .rm (toward −∞), .rp (toward +∞). Use cases:

  • .rn — default, lowest expected error.
  • .rz — required by some quantization schemes that want symmetric clipping.
  • .rm/.rp — interval arithmetic, error bounds.

Rounding mode is part of the SASS instruction; you cannot change it at runtime. Set it per-FMA with intrinsics like __fmul_rn, __fmaf_rz.

[A12.1.2]

Subnormals & Flush-to-Zero

denormals

Numbers smaller than the smallest normal float (2−126 for FP32) are subnormals. They preserve relative precision near zero, but on most hardware they cost extra cycles. NVIDIA GPUs handle subnormals at full speed for FP32 add/multiply on sm_53+, but a few transcendentals are flushed to zero unconditionally.

The -use_fast_math flag enables FTZ globally: every operation that would produce a subnormal returns ±0. This is fine for inference and most training, but breaks careful numerical code (Kahan summation, ill-conditioned linear solvers).

To probe what FTZ is doing, check __float_as_uint(x) after an arithmetic op and look for the exponent field being all zero with non-zero mantissa — that is a subnormal.

[A12.1.3]

ULP — The Currency of Error

error analysis

One unit in the last place (ULP) is the gap between two adjacent representable floats. For FP32 at magnitude 1.0, 1 ULP ≈ 1.19e−7. A correctly rounded operation has error ≤ 0.5 ULP. NVIDIA documents the max ULP error of every intrinsic in the CUDA Math API; e.g. __expf is 2 ULPs while expf is < 1 ULP. When you read "tolerance of 1e-5" in a unit test, translate it: at magnitude 1, that's ~84 ULPs of slack. At magnitude 10⁶, the same absolute tolerance accepts ~8 ULPs.

12.2FMA Semantics & Why Multiply-Then-Add ≠ FMA

A single rounding step changes more than you'd think

[A12.2.1]

Fused Multiply-Add

FMA

fma(a,b,c) computes a*b + c with a single rounding step at the end. Plain a*b + c in C++ rounds twice. The difference can be 1 ULP per operation, which is everywhere in GEMM (millions of FMAs). The reason your CUDA result differs from your CPU reference is often that nvcc fused multiply-adds while gcc didn't.

Force FMA on/off when reproducing bug reports:

  • nvcc -fmad=false — disable contraction. Useful to match a CPU reference compiled with -ffp-contract=off.
  • __fmul_rn(a,b) + c — explicit unfused multiply, then add.
  • __fma_rn(a,b,c) — explicit fused.

12.3Summation Algorithms — When Floats Stop Associating

Naive, pairwise, Kahan, and Neumaier compared

[A12.3.1]

Why Order Matters

numerical stability

FP addition is non-associative: (a+b)+c ≠ a+(b+c) in general. The relative error of a naive serial sum of N positive FP32 numbers is bounded by N · ε where ε = 2⁻²⁴. With N = 2²⁴ ≈ 16M, you can lose all precision. Better algorithms cap or shrink this dependence on N.

// Warp-level Kahan reduce. 32 threads, each holds val; output = sum across warp.
__device__ float warp_kahan_sum(float val) {
    float sum = val;
    float c   = 0.0f;                    // running compensation
    for (int offset = 16; offset > 0; offset >>= 1) {
        float other_sum = __shfl_down_sync(0xffffffff, sum, offset);
        float other_c   = __shfl_down_sync(0xffffffff, c,   offset);
        float y = other_sum - (c + other_c);
        float t = sum + y;
        c = (t - sum) - y;               // bits lost going into t
        sum = t;
    }
    return sum;                          // lane 0 holds the answer
}
Tensor Cores accumulate in FP32 — be aware

An FP16×FP16 → FP32 Tensor Core operation multiplies in FP16 (3 decimal digits of precision) but accumulates in FP32. The accumulation chain is hardware-pairwise across the 8/16/32 K-axis steps, so a single mma.sync is well-behaved. The problem comes in the K loop: how many mma.sync calls feed the same FP32 accumulator? After ~10⁴ calls you may lose accuracy in the low bits.
