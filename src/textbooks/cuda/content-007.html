What each piece does — in one sentence

  • CUDA core (FP32 lane). One floating-point multiply-add per clock. Your scalar workhorse.
  • Tensor Core. A whole small matrix multiply-accumulate per clock. Where the real teraflops live.
  • Register file. The fastest memory on the chip. Each thread owns a slice.
  • Shared memory. Software-managed scratchpad. Programmer-controlled cache.
  • Warp scheduler. Picks one eligible warp per cycle and issues an instruction.
  • Dispatch unit. Sends the instruction to the right execution pipe.
  • Load/Store unit. Issues memory transactions to L1/L2/DRAM.
  • SFU. Computes sin, cos, rcp, rsqrt on its own pipe so they don't block the FP32 cores.

Per-SM resource counts above are for GA10x-class Ampere parts (RTX 3090, RTX 30-series). Why this matters for your kernel
Every choice you make later — block size, shared-memory layout, tile shape, register pressure — is really a choice about how to fill one of those sub-partitions with eligible warps and useful work. When Nsight Compute later tells you "Warp State: long_scoreboard 60%," what it is really saying is "the warp scheduler for some sub-partition keeps looking for a ready warp and finding none, because every warp is waiting on global memory."
